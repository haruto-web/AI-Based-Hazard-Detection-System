===============================================================================
CAMERA IP SECURITY WITH SHA-256 HASHING
ESP32-CAM IP Protection Guide
===============================================================================

OVERVIEW:
---------
Your camera IPs (like "192.168.254.144") are now hashed with SHA-256 before
storage in Firestore. This prevents:
- Unauthorized access to camera locations
- IP address theft from database breaches
- Direct camera access without proper authentication

===============================================================================
HOW IT WORKS
===============================================================================

1. USER ENTERS CAMERA IP
   ----------------------
   User inputs: "192.168.254.144"
   
2. SHA-256 HASHING
   ----------------
   System creates hash: "a7b3c9d2e8f1..." (64 characters)
   Salt: User ID (unique per user)
   
3. DUAL STORAGE
   -------------
   Firestore (permanent): Stores ONLY the hash
   SessionStorage (temporary): Stores actual IP (cleared on browser close)
   
4. STREAM CONNECTION
   ------------------
   System retrieves IP from sessionStorage → connects to camera
   If sessionStorage cleared → user must re-enter IP

===============================================================================
SECURITY BENEFITS
===============================================================================

✅ DATABASE BREACH PROTECTION
   - If Firestore is compromised, attackers only see hashes
   - Cannot reverse-engineer actual IP addresses from hashes
   - Each user's IPs salted differently (user ID)

✅ SESSION-BASED ACCESS
   - Actual IPs stored only during active browser session
   - Automatically cleared when browser closes
   - No persistent plain-text IP storage

✅ UNIQUE HASHING PER USER
   - Same IP address = different hashes for different users
   - Cannot correlate IPs across users
   - Salt prevents rainbow table attacks

EXAMPLE 1: STORE CAMERA IP (When user configures camera)
---------------------------------------------------------
import { storeCameraIPSecurely } from './utils/cameraSecurity';

async function handleCameraSetup(userId, cameraIndex, ipAddress) {
  // Validate and hash IP
  const result = await storeCameraIPSecurely(userId, cameraIndex, ipAddress);
  
  if (result.success) {
    console.log('✅ Camera IP stored securely');
    console.log('Hash:', result.hash);
    // Firestore now has: "a7b3c9d2e8f1..." instead of "192.168.254.144"
  } else {
    console.error('❌ Failed:', result.message);
  }
}

EXAMPLE 2: RETRIEVE CAMERA IP (When connecting to stream)
----------------------------------------------------------
import { getCameraIP, buildStreamURL } from './utils/cameraSecurity';

function connectToCamera(userId, cameraIndex) {
  // Get IP from sessionStorage
  const ip = getCameraIP(userId, cameraIndex);
  
  if (!ip) {
    alert('Please configure camera IP first');
    return;
  }
  
  // Build stream URL
  const streamURL = buildStreamURL(ip, '81');
  // streamURL = "http://192.168.254.144:81/stream"
  
  // Connect to camera
  videoElement.src = streamURL;
}

WHY SESSION STORAGE?
- Cleared automatically when browser closes
- Not accessible to other tabs (private to current session)
- Not persisted to disk like localStorage
- More secure for sensitive data

===============================================================================
QUESTIONS & ANSWERS
===============================================================================

Q: Why not encrypt IPs instead of hashing?
A: Hashing is one-way (cannot be reversed). Encryption requires storing
   keys, which could be compromised. Hashing is more secure for this use case.

Q: What if I lose the IP after browser closes?
A: Users need to re-enter camera IPs after browser closes. This is a
   security feature, not a bug. It prevents unauthorized access.

Q: Can I retrieve the original IP from Firestore?
A: No, that's the point! Hashes cannot be reversed to get original IPs.
   Only the current session has access to actual IPs.

Q: Will this slow down camera connections?
A: No. Hashing happens once during IP entry. Connections use cached IP
   from sessionStorage (no hashing involved).

Q: What about multiple browser tabs?
A: sessionStorage is shared across tabs in the same origin. IPs will
   be accessible in all tabs until browser closes.

Q: How do I change a camera IP?
A: Just enter the new IP - it will hash and update automatically.
